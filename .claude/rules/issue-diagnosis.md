# 이슈 진단 원칙

vault ISSUE는 **가설**이다. 보고된 증상은 종종 작성 시점(과거) 코드 기준이라:

- 이미 다른 작업으로 **수정됐거나**,
- **의도된 동작**이라 결함이 아니거나,
- 현재 코드에선 **다른 양상**일 수 있다.

## 수정 전 반드시 현재 코드로 원인을 검증한다

- 증상을 재현·추적해 실제 근본 원인을 코드에서 확인한다 (`file:line` 인용).
- **"이게 진짜 결함인가?"를 먼저 묻는다** — 결함이 아니면 수정하지 말고 close/문서화를 제안 (헛수정 방지).
- 검증 결과가 vault 설명과 다르면, 그 차이를 사용자에게 보고한 뒤 진행한다.
- 단일 프레임·타이밍 버그는 **재현 창을 넓혀** 관찰한다 (예: DevTools Network를 Slow 3G로 두면 async 대기 구간이 늘어나 한 프레임짜리 중간 상태가 수 초간 보인다).

> 근거: 헛수정 방지 + 오래된 리포트의 stale 증상 식별. 모든 세션(BE/FE/DE) 공통.
