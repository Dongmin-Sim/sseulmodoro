# 작업 워크플로우 원칙 (태스크·이슈 공통)

APP 트랙(Claude 구현)의 태스크·이슈 작업에 공통 적용한다.

- **진단 우선 (이슈):** 수정 전 현재 코드로 원인을 검증한다 — 이슈 spec는 가설. (`rules/issue-diagnosis` 참조)
- **plan 모드 게이트:** 여러 파일·구조 변경·접근 선택지가 있는 작업은 구현 전 plan을 작성하고 **ExitPlanMode로 승인**받은 뒤 구현한다.
- **검증 3종 (커밋 전 필수):** `npm run build` + `npm run lint` + `npm test` — 에러 0 확인.
- **사용자 확인 (QA):** 커밋 전 재현·확인 절차를 안내하고 사용자 확인을 받는다. 타이밍·단일프레임 같은 버그는 재현 창을 넓혀(예: DevTools Slow 3G) 확인 가이드를 제공한다.
- **PR 초안 우선:** PR 생성 전 제목·본문 초안을 사용자에게 먼저 보여주고 승인받는다.
- **stacked 브랜치:** 직전 작업이 dev 머지 전이고 다음 작업이 그 위에 의존하면, 미머지 브랜치에서 분기 → 직전 PR 머지 시 dev로 rebase.
- **커밋 위생:** 작업 관련 파일만 스테이징. 로컬 전용 설정은 `settings.local.json`(gitignore)에 두고 `settings.json`엔 머신 절대경로/개인 권한을 커밋하지 않는다.
