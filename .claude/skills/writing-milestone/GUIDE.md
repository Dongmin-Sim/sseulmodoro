# writing-milestone — section guide

Reference when filling `TEMPLATE.md`. Write declaratively — a milestone reads as a directive, not a compressed recap of the session that produced it.

- **의의** — two lines: what this milestone means to the *project* (not the user), and what capability the *user* gains from it (project value + learning value).
- **도달 정의** — one verifiable sentence: what makes this "reached".
- **진행 단계** — checkboxes on the way to reaching it.
- **관련 Task** — the tasks grouped under this milestone (IDs).
- **미정 사항** — what's undecided + when it will be decided.
- **진행 메모** — decisions/adjustments/lessons accrued with dates; record big decisions inline. On reaching, add a light retro (thought it through? / learned? / what first next time? / what to improve?) — items 1 & 3 are interview material.
