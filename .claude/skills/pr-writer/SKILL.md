# pr-writer

커밋 메시지와 PR 본문을 **일관·가독성** 있게 작성하는 절차. 커밋·PR 생성 직전에 참조.

목표: 코드 변경의 **핵심**을 빠르게 전달. 상세 구현은 코드/diff가 말하게 두고, 본문은 What·Why 요약에 집중.

## 4대 원칙

1. **요약식 (What·Why 중심)**
   - 무엇을·왜 바꿨는지가 본체. *어떻게(How)*의 구현 디테일은 적지 않음 — 리뷰어는 본문으로 맥락을 잡고 코드로 상세를 본다.
   - 금지: 파일별 줄줄 나열, 괄호 안 구현 디테일(`(requireInteraction·tag·아이콘)` 같은 것), 함수명·내부 변수 나열.
   - 변경이 크면 산문 대신 **모듈/주제 단위 불릿**으로 쪼갠다.

2. **배경 모르는 사람 기준**
   - 이 PR·대화·vault 맥락을 모르는 사람이 읽어도 이해되게.
   - 금지: 내부/대화 맥락 언어 — "3번 결정은 다음으로 이월", "아까 그 이슈", "vault 정합", 내부 약어.
   - 허용: `TASK-{N}`·`ISSUE-{N}` 번호는 **관련 태스크 섹션에서만** 참조(본문 산문에 섞지 않음).

3. **개조식·명사형 종결**
   - 구어체·설명체 금지. 명사형으로 끝맺음.
   - 나쁨: "~하도록 수정했습니다", "~던 문제를 해결함", "~인 것 같아서 바꿈"
   - 좋음: "백그라운드 탭 완료 미발생 결함 수정", "완료 트리거를 setTimeout 기반으로 전환"

4. **한 PR = 한 주제**
   - 스코프를 한 문제로 좁힌다. 곁다리 변경은 분리.

## 작성 흐름 (초안 → 승인 → 생성)

1. **초안 출력** — 제목·본문 초안을 터미널에 먼저 보여준다. 바로 생성 금지.
2. **사용자 리뷰·수정** — 승인 또는 수정 지시를 받는다.
3. **윤문** — 한글 본문은 `humanize-korean` 스킬을 거친다. 단 PR 본문은 **개조식 우선**이라 산문화하지 않게 주의(과윤문 방지).
4. **생성** — 승인 후 `gh`로 생성.
   - PR 생성: `gh pr create --base dev --title "..." --body-file <임시파일>`
   - **본문 수정은 `gh pr edit` 금지**(이 레포는 Projects classic 오류로 실패) → `gh api -X PATCH repos/{owner}/{repo}/pulls/{N} -f body=...` 사용.

## 커밋 메시지 규칙

- 형식: `type(scope): 내용` — type = feat/fix/refactor/style/chore/docs/test
- 제목 50자 이내, **명령형**("추가", "수정" 동사로 시작)
- 본문은 필요 시에만. Why를 짧게.
- **금지**: `Co-Authored-By: Claude ...` 트레일러, "Generated with Claude Code" 류 푸터.
- 관련 이슈 있으면 footer에 `Closes #이슈번호`.

## PR 제목 규칙

- 형식: `[TASK-{N}] 태스크명` 또는 `[ISSUE-{N}] 이슈명` (ID 비패딩)
- 예: `[TASK-21] 캐릭터 뽑기 DB/API 구현`, `[ISSUE-5] 로그아웃 경고 복원`

## PR 본문 구조

`.github/pull_request_template.md` 섹션을 따른다. 작성 시 주의:

- **Summary** — What·Why 불릿. 결함 PR이면 증상·원인 1줄씩.
- **작업 내용** — 모듈/주제 단위 한 일만 담백하게. 구현 디테일·근거·트레이드오프는 넣지 않음.
- **선행 PR / 관련 태스크** — 번호만.
- **후속 작업** — 이번에 못 한 것·알려진 한계. 없으면 섹션 삭제.
- **Test plan** — `build`/`lint`/`test` + 수동 확인 항목 체크박스.
- vault 정합·운영/인프라 설정 상태 같은 **내부 메타는 PR 아닌 handoff 채널로**.

## Before / After (요약식 적용 예)

나쁨 (구현 디테일 나열):
```
- notify.ts(신규): 알림 유틸 분리 — OS 알림(requireInteraction·라운드별 tag·아이콘),
  페이지 내 사운드(파일 우선 → Web Audio 비프 폴백), 백그라운드 시 탭 제목 깜박임 +
  소리 5초 반복(복귀 시 정지, 2분 캡)
```
좋음 (요약):
```
- notify.ts(신규): 백그라운드 완료 알림 분리 — 소리·탭 제목 깜박임·OS 알림
```

## 체크리스트 (생성 전)

- [ ] 제목이 `[TASK-N]`/`[ISSUE-N]` 컨벤션을 따르는가
- [ ] 본문에 내부/대화 맥락 언어가 없는가 (배경 모르는 사람이 읽혀지는가)
- [ ] 구현 디테일 대신 요약식인가
- [ ] 개조식·명사형 종결인가
- [ ] Claude 푸터·Co-Authored-By 트레일러가 없는가
- [ ] 초안을 사용자가 승인했는가
