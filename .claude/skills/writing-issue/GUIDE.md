# writing-issue — section guide

Reference when filling `TEMPLATE.md`. An issue is a **hypothesis** until verified against current code (`rules/issue-diagnosis`) — the reported symptom may already be fixed, intended, or different now.

- **증상** — what behaves wrong, with the trigger conditions.
- **재현 방법** — numbered steps.
- **원인** — the analysis, confirmed in current code (`file:line`).
- **수정 내용** — what was changed to fix it.
- **검증** — checkboxes: how the fix was confirmed.
- **참고** — related decision / related issue. workspace paths / IDs (not Obsidian wikilinks).
